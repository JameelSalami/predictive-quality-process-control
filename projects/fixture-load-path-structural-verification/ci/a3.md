# A3

## Background

Final inspection tells an engineer what the process produced, but often after material, machine time, and downstream value have already been committed. This project therefore treats quality as a control loop rather than a final inspection step.

## Current condition

Real public DED-LB data establish one bounded result:

- 23 same-track runs;
- 4,905 laser-active IR frames;
- recipe-only held-out bead-width RMSE 0.4683 mm;
- recipe + IR held-out RMSE 0.4279 mm;
- 8.64% relative RMSE reduction inside the selected process window;
- unseen-speed held-out R² remains negative.

The real data do not contain a valid production MSA study, production population, or engineering specification limits. Capability and SPC are therefore not assessable for the public DED treatment.

## Problem statement

Build a reusable manufacturing-quality workflow that:

1. preserves process/run/CTQ identity;
2. validates whether in-process sensing adds predictive information;
3. refuses downstream quality metrics when evidence is missing;
4. qualifies the measurement system before trusting process statistics;
5. separates process stability from product specifications;
6. detects special causes and invokes a reaction plan before automatic production restart.

## Countermeasure

A process-agnostic quality-control engine now implements:

```text
CTQ definition
→ MSA
→ stable baseline
→ capability
→ SPC
→ OCAP
→ requalification
```

Effect orchestrates the analytical gates. XState models only the event-driven operational lifecycle.

## Demonstration

A synthetic-only downstream control fixture shows the workflow without fabricating claims about the public DED data.

The first synthetic SPC alarm occurs at 10.26 mm while the synthetic product specification remains 9.4–10.6 mm. This demonstrates why control limits and specification limits must remain separate.

## Follow-up

A real deployment should replace the demo policy with product/customer requirements, select control charts from the actual sampling structure and process dynamics, and bind OCAP actions to approved work instructions and production traceability.
